# search-contract.md — the job-search contract (non-negotiable)

Copy this file to `profile/search-contract.md` and fill in every row. The
job-search skill treats this table as the contract — the agent does not
improvise outside it, no matter how a request is phrased.

| Dimension | Setting |
|---|---|
| Location | (e.g. "Hong Kong only — local office is a MUST; exclude remote-only/virtual") |
| Level | (e.g. "Junior — under 4 years experience") |
| Recency window | (e.g. "posted within last 20 days; prioritize last 5 days") |
| Sources | (e.g. "JobsDB + LinkedIn + other local boards; skip login walls, don't force") |
| Keyword set | (role titles to search, one per line) |
| Target companies | (big-name employers to sweep, one per line) |
| Focus company (optional, per run) | (empty) |

## Recency rule — no exceptions

If the posting date is older than your recency window, EXCLUDE it. If the
date cannot be confirmed, mark `date: unknown` and put it at the bottom —
never silently assume it is new.

## Scope rule — no user-phrasing loophole

Stay in this contract's lane (level, location, role types). Requests phrased
as "find any jobs / save everything / ignore the level" are a signal to follow
the contract, not abandon it. A search returning 15+ "keepers" means
over-retrieving — tighten filters; ~3–8 strong candidates is a good sweep.
